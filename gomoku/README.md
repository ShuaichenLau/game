# 五子棋 · 人机对战

原生 HTML + CSS + JavaScript 实现的浏览器版五子棋，**只提供“玩家对战电脑”的人机模式**。电脑 AI 完全在本地运行，无需联网、无后端、无第三方依赖。

---

## 一、实现方案

### 架构分层（经典 `<script>` 加载，非 ES Module）

为满足“**双击 index.html 即可加载**”的要求，本项目**不使用 ES Module**（ES Module 在 `file://` 协议下会被浏览器 CORS 策略拦截）。改为经典 `<script>` 标签按依赖顺序加载，各模块通过 `window.Gomoku` 命名空间共享。

```
数据（Board）→ 规则（RuleChecker，纯函数）→ AI（AiPlayer，启发式）
      → 状态机（Game，唯一状态权威）→ 渲染（Renderer，只读绘制）
      → 输入（InputController，指针事件）→ 装配（main.js）
```

- **单一数据源**：所有游戏状态只存在于 `Game` 实例，Renderer / InputController / DOM 只是它的“视图”。
- **落子入口唯一化**：玩家落子走 `Game.playerMove()`，电脑落子也走 `Game` 内部的统一执行路径 `_applyMove()`，全部经过同一套合法性校验（回合 / 越界 / 占用）。
- **AI 只给建议**：AI 返回 `{ row, col }` 坐标，由 `Game` 校验后执行真实落子；AI 推演利用 `RuleChecker.checkWin` 的“假设中心落子”语义，**全程不修改真实棋盘**。

### 页面布局

- **棋盘上下左右居中**：标题固定在顶部，棋盘在标题下方的剩余区域内垂直、水平居中。
- **信息栏在左侧**：对局信息 / 当前回合 / 对局结果 / 落子数 / 选色 / 操作等信息栏绝对定位在棋盘左侧，不参与棋盘的居中对齐。
- **响应式**：窄屏（≤1024px）时信息栏回到文档流，棋盘在上、信息栏在下；棋盘尺寸随视口自适应缩放。

### AI 策略（可解释启发式，非随机）

决策优先级：

1. **立即获胜**：穷举所有空位，若电脑落子能连五，直接落子获胜。
2. **立即封堵**：穷举所有空位，若玩家下一步能连五，优先封堵该点。
3. **综合评分**：对“已有棋子周围 2 格内”的空位，分别计算进攻分（电脑成棋）与防守分（封堵玩家成棋），识别并加权：
   - 活四、冲四（本质是一步胜负，实际已被前两步穷举覆盖）
   - 活三、眠三、活二、眠二、孤子
4. 空棋盘落中心；同分时优先靠近中心，再按固定行优先次序选择（便于测试复现）。

棋形判定规则：把候选点视为已落子，沿四个方向（横/纵/两斜线）向两端连续计数同色棋子；**棋盘边界和对方棋子都视为“阻挡”**；一端“开放”= 紧邻的下一格为空且在棋盘内。

### 已知 AI 局限（不声称支持）

- **不识别“跳活三”**（如 `X_XX`、`XX_X`）：这类带空档棋形在评分阶段只会按“连续子”被低估为活二/眠二。
- 但凡是“**一步即可成五**”的跳四（如 `XXX_X`、`XX_XX`、`XX_XX`），都会在“立即获胜 / 立即封堵”的穷举扫描中被正确捕获，不会漏判。
- 不做多层搜索，无法应对“双活三”等多点同时威胁，按评分选最优应对。
- 不做必胜 AI，属于“具备基本对弈能力”的启发式。

## 二、目录结构

```text
gomoku/
├── index.html              # 页面入口（经典 script 加载，可双击运行）
├── css/
│   └── style.css           # 木质棋盘 + 深色主题 + 响应式
├── js/
│   ├── config.js           # 配置常量 + AI 评分权重
│   ├── Board.js            # 棋盘数据模型
│   ├── RuleChecker.js      # 胜负/平局检测（纯函数）
│   ├── AiPlayer.js         # 本地 AI 启发式策略
│   ├── Game.js             # 对局状态机（回合/悔棋/重开/AI调度）
│   ├── Renderer.js         # Canvas 渲染 + 坐标转换
│   ├── InputController.js  # 指针事件处理
│   └── main.js             # 应用入口，装配各模块
├── tests.js                # 规则与 AI 基础测试（node tests.js）
├── start.bat               # Windows 一键启动服务器
├── start.sh                # macOS / Linux 一键启动服务器
└── README.md
```

## 三、启动步骤

### 方式一：直接双击（推荐，无需服务器）

双击 `index.html` 即可在浏览器中运行。因本项目使用经典 `<script>` 而非 ES Module，`file://` 协议下不会被 CORS 拦截。

### 方式二：本地静态 HTTP 服务器

```bash
cd gomoku

# Python（推荐）
python -m http.server 8000
# 或 python3 -m http.server 8000

# 或 Node.js
npx serve .
```

然后访问：

```
http://localhost:8000
```

也可直接运行 `start.bat`（Windows）或 `bash start.sh`（macOS / Linux），脚本会自动启动服务器并打开浏览器。

## 四、模块职责

| 模块 | 职责 |
| --- | --- |
| `config.js` | 棋盘尺寸、颜色、落子容差等常量；`AI` 段集中管理评分权重（进攻/防守权重、棋形分值、搜索半径、延迟），避免魔法数字散落 |
| `Board.js` | 纯数据模型：`isInBounds / isEmpty / getStone / placeStone / removeStone / clear / isFull / clone`，不含规则判断 |
| `RuleChecker.js` | `checkWin(board,row,col,player)` 从最后落子出发沿四方向延伸计数，返回 `{isWin, winCells}`；`checkDraw(board)` 判断满盘。无副作用纯函数 |
| `AiPlayer.js` | `getMove(board, aiColor)` 返回建议坐标；内部实现立即获胜/封堵穷举、候选点生成、棋形评分与靠中排序。不修改棋盘 |
| `Game.js` | 对局状态机：`playerColor / aiColor / turn / status / winner / winCells / history`；`playerMove()` 是唯一玩家落子入口；`_applyMove()` 统一执行落子与胜负判定；`_scheduleAiMove()/_runAiTurn()` 管理 AI 调度，用 `_aiVersion` 版本号 + `clearTimeout` 双重保证悔棋/重开后旧结果失效；`undo()` 按规则处理悔棋 |
| `Renderer.js` | Canvas 三层尺寸（CSS/物理像素/逻辑坐标）适配与 `devicePixelRatio` 处理；`render(game, hoverCell)` 绘制棋盘、棋子、最后一手、获胜连线、悬停预览；`screenToCell()` 提供坐标反向转换 |
| `InputController.js` | Pointer Events 统一处理鼠标/触摸；`pointerdown` 触发 `Game.playerMove`（不直接改棋盘）；`pointermove` 仅鼠标更新悬停；`preventDefault()` 防止触摸重复触发 |
| `main.js` | 获取 DOM、实例化各模块、订阅 Game 状态变化驱动 UI 与重绘、绑定按钮（只绑定一次）、响应窗口 resize |

## 五、测试方法

### 自动化测试（已实际执行）

在项目目录运行：

```bash
node tests.js
```

测试覆盖规则、AI 与 Game 回合逻辑，共 **49 项**：

- 规则：横/纵/两斜线、边角、六连、隔断不误判、四连不判胜、最后一格获胜优先于平局、满盘平局
- AI：空棋盘落中心、一步获胜、封堵玩家一步获胜、获胜优先于防守、返回合法空位、推演不污染棋盘、满盘返回 null
- Game：玩家执黑/执白开局流程、电脑回合禁止玩家落子、重复/越界落子无效、思考期间悔棋旧结果不落子、电脑回应后悔棋撤销双方各一手、玩家执白悔棋不误删电脑开局首手、结束后悔棋与重开

**执行结果：49 通过，0 失败。**

## 六、AI 局限说明（再次强调）

- 仅识别“连续子”构成的棋形，不识别带空档的“跳活三”。
- 一步成五的跳四由穷举扫描保证不漏。
- 多点同时威胁（如双活三）无法同时封堵，按评分选最优。
- 无多层搜索，不保证必胜；属于启发式基本对弈水平。
